# A few custom workflows I rely on

These are public summaries of local skills used across personal projects and data-engineering work. They explain the method without publishing private instructions, systems, or source material.

| Workflow | What it changes |
| --- | --- |
| Business reconstruction | Read the actual conversations and documents, reconstruct the operating process, then show concrete cases and missing handoffs. |
| Clarify intent | Turn a rough request into the intended outcome without replacing it with a generic task or asking questions the context already answers. |
| Durable change validation | Test the affected behavior, inspect the real deployed result, and distinguish a local edit from a verified release. |
| Visual explanation handoff | Supply verified facts, a precise confusion, a reference with reasons, and a worked example; inspect the artifact before sharing it. |
| System documentation | Define source systems, show ownership and unit-specific differences, preserve useful examples, and keep technical evidence close to its claim. |

The reusable public visual workflow is [SKILL.md](../SKILL.md). These summaries are not separate installed skill packages or a claim that instructions enforce themselves.
